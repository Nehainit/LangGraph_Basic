# Generation model selectors and pricing

**Date:** 2026-09-29  
**Status:** Design approved in conversation; awaiting document review  
**Scope:** Add user-facing model choices for narration, image generation, and video generation.

## Goal

Let a user choose which supported generation model a video run uses for narration, still images, and animated shots. Show each model's current published price and billing unit alongside its option. The selected choices must reach the generation agents and determine the actual models used.

## Current behavior

- The composer has one `image_provider` select for Magnific or fal.ai. That value controls both shot images and shot videos.
- Image generation uses Magnific Nano Banana Pro Flash or fal Nano Banana Pro, selected by provider. Image resolution follows Standard/High quality (1K/2K).
- Video generation uses Magnific Kling 2.6 or fal Kling 2.6 Pro, selected by the same provider. Generated clips are 5 or 10 seconds; native audio is disabled.
- Narration uses ElevenLabs Flash v2.5 by default, with an environment override. `create_narration` already reads an ElevenLabs TTS model from graph state, but the web request does not expose it.

## User experience

Replace the single combined image/video provider control with three selectors:

1. **Narration model** — ElevenLabs Flash v2.5 (default) and Multilingual v2.
2. **Image model** — Magnific Nano Banana Pro Flash (default) and fal Nano Banana Pro.
3. **Video model** — Magnific Kling 2.6 (default) and fal Kling 2.6 Pro.

Stable IDs are `eleven_flash_v2_5`, `eleven_multilingual_v2`, `nano-banana-pro-flash`, `fal-ai/nano-banana-pro`, `kling-v2-6-pro`, and `fal-ai/kling-video/v2.6/pro/image-to-video` respectively. These identifiers are application-owned allowlist values, not arbitrary provider endpoints.

Each option names both its provider and model, and includes a unit-aware rate. Rates adapt to the existing quality setting where necessary: image options display the price for the selected 1K or 2K output, and video options display a per-second rate. The narration rate is per 1,000 input characters.

Published rates captured for this design:

| Stage | Option | Displayed rate |
| --- | --- | --- |
| Narration | ElevenLabs Flash v2.5 | $0.05 / 1,000 characters |
| Narration | ElevenLabs Multilingual v2 | $0.10 / 1,000 characters |
| Image | Magnific Nano Banana Pro Flash | $0.095 / image at 1K; $0.143 / image at 2K |
| Image | fal Nano Banana Pro | $0.15 / image at 1K or 2K |
| Video | Magnific Kling 2.6 | 45 Magnific credits / second at 1080p |
| Video | fal Kling 2.6 Pro | $0.07 / second with audio disabled |

Prices are indicative public API rates, not an invoice or a total run estimate. Magnific video uses credits rather than USD in its published model pricing. Show that native unit as-is instead of inventing a USD conversion that depends on account and credit plan. The rates are catalog data maintained with the application and may need manual updates when a vendor changes pricing.

Sources: [ElevenLabs API pricing](https://elevenlabs.io/pricing/api?price.platform=api), [Magnific API pricing](https://www.magnific.com/cn/api/pricing), [Magnific video credits](https://www.magnific.com/zh/ai/docs/ai-video-generator-credits), [fal Nano Banana Pro pricing](https://fal.ai/nano-banana-pro), and [fal Kling 2.6 image-to-video pricing](https://fal.ai/models/fal-ai/kling-video/v2.6/pro/image-to-video).

## Request and execution behavior

- Add an application-owned, read-only model catalog endpoint. Its entries contain stage, provider, stable model ID, display name, and cost metadata (amount, currency or provider credit unit, billing unit, and any quality-specific rates).
- The frontend loads that catalog and builds the three selectors from it. Price text and selection metadata therefore come from the same catalog.
- The create-video request sends one model ID per stage. The backend validates every ID against the server-side catalog; browser-provided provider names, endpoint URLs, or prices are never trusted.
- Carry validated model choices in graph state and dispatch each stage independently. Image and video selections can now use different providers in the same run.
- Keep legacy requests working. If a caller supplies only the legacy `image_provider`, it selects that provider's currently integrated image and video models. If no new model IDs and no legacy provider are supplied, use today's defaults. When a caller supplies either new image or video model ID, default only the other omitted stage to its current default. Existing CLI/API callers therefore continue to work while new callers can choose image and video providers independently.
- Include selected provider and model in generation metadata and cache metadata. A changed model must not reuse an artifact generated by a different model.
- Never expose provider API keys to the browser. Provider calls remain server-side.

## Pricing and error behavior

- Treat prices as display estimates from the maintained catalog. Do not fetch vendor model lists or prices from the browser at runtime.
- Show billing units clearly: characters, images, seconds, or Magnific credits. Reflect the current image quality in image price labels.
- Keep the selectors usable without leaking or requiring any credentials in the browser. Credential validation remains at the point the chosen provider is used.
- Reject unknown model IDs before generation with a clear request validation error. Existing selection defaults should keep old requests valid.

## Out of scope

- Arbitrary model IDs or every model listed by Magnific, fal, or ElevenLabs.
- Live vendor catalog or pricing synchronization.
- Total project cost prediction, budget caps, currency conversion, or cost billing/charge collection.
- Changing generation quality, prompting, or provider behavior beyond selecting the supported model for a stage.

## Acceptance criteria

- The composer shows independent narration, image, and video model selectors, with the current models selected by default.
- Every option shows its provider, model, rate, and billing unit; image rates reflect Standard/High resolution.
- Choosing a model changes the model used by the corresponding backend stage, independently of the other stages.
- Unknown IDs are rejected server-side, and legacy requests that omit the new fields continue to use today's behavior.
- Generation and cache provenance records the selected model so artifacts cannot be mistaken for outputs from a different selection.
- No secrets are returned to or used by frontend code.
